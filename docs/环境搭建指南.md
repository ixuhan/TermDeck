# TermDeck 环境搭建指南

> 目标：在一台干净的 Windows 10/11 x64 机器上，从零把 TermDeck 跑起来。
> 所有命令可直接粘贴到 **PowerShell**。需要管理员的步骤会单独标注。

---

## 0. 当前这台机器已经装好的部分

| 组件 | 位置 | 状态 |
| --- | --- | --- |
| Node.js 22 / npm 10 | 系统 | ✅ 已有 |
| 前端依赖 `node_modules` | `F:\TermDeck\node_modules` | ✅ 已装（46 包） |
| Rust 1.99 工具链 | `F:\TermDeck\.toolchain\rustup`（1.5 GB） | ✅ 已装 |
| Cargo 主目录 + crates 缓存 | `F:\TermDeck\.toolchain\cargo`（560 MB） | ✅ 已装 |
| VS 2022 生成工具 + Win11 SDK | `C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools` | ✅ 已装（3.6 GB） |
| 用户目录残留 `.cargo` / `.rustup` | — | ✅ 已清理，未占用系统目录 |

**所以你这台机器只差最后一步：把 Rust 编译完。**

```powershell
cd F:\TermDeck
scripts\build.bat
scripts\run.bat
```

编译耗时约 **8–15 分钟**（首次要下 400+ 个 crate）。完了直接双击 `scripts\run.bat` 就能开窗口。

下面第 1–6 节是**换一台新机器时的完整流程**，留档用。

## 1. 前置检查

```powershell
node -v          # 需要 >= 20
npm -v
```

Node 没装的话：

```powershell
winget install OpenJS.NodeJS.LTS -e
```

## 2. npm 源改成国内镜像

官方 registry 在国内基本拉不动（实测 8 分钟装了 0 个包）。

工作区里已经有 `.npmrc`，内容就三行，**不用额外操作**：

```ini
registry=https://registry.npmmirror.com
cache=F:/TermDeck/.cache/npm
fund=false
```

新机器上请确认这个文件存在，然后再：

```powershell
cd F:\TermDeck
npm install
```

---

## 3. 安装 Rust（装进工作区，不碰系统目录）

> ⚠️ **坑 1**：`static.rust-lang.org` 的二进制下载在国内会被中断（`curl` 直接 SIGTERM，无任何报错）。必须用 rsproxy 镜像。

```powershell
$env:RUSTUP_DIST_SERVER = "https://rsproxy.cn"
$env:RUSTUP_UPDATE_ROOT  = "https://rsproxy.cn/rustup"

# 关键：先把 CARGO_HOME / RUSTUP_HOME 指向工作区，rustup 就会装到这里
$env:CARGO_HOME  = "F:\TermDeck\.toolchain\cargo"
$env:RUSTUP_HOME = "F:\TermDeck\.toolchain\rustup"
New-Item -ItemType Directory -Force -Path "F:\TermDeck\.toolchain" | Out-Null

Invoke-WebRequest -Uri "https://rsproxy.cn/rustup/dist/x86_64-pc-windows-msvc/rustup-init.exe" `
  -OutFile "$env:TEMP\rustup-init.exe"

& "$env:TEMP\rustup-init.exe" -y --default-host x86_64-pc-windows-msvc --profile default --no-modify-path
```

`--no-modify-path` 是有意的：不往系统 PATH 里塞东西，改由脚本临时注入。

**验证**（注意必须带环境变量，否则会找不到工具链）：

```powershell
$env:CARGO_HOME="F:\TermDeck\.toolchain\cargo"; $env:RUSTUP_HOME="F:\TermDeck\.toolchain\rustup"
& "F:\TermDeck\.toolchain\cargo\bin\cargo.exe" --version
# 期望: cargo 1.99.x
```

如果这条报 `no default is configured`，补一句：

```powershell
& "F:\TermDeck\.toolchain\cargo\bin\rustup.exe" default stable-x86_64-pc-windows-msvc
```

---

## 4. 配置 crates 源

新建 `F:\TermDeck\.toolchain\cargo\config.toml`：

```toml
[source.crates-io]
replace-with = "rsproxy-sparse"

[source.rsproxy-sparse]
registry = "sparse+https://rsproxy.cn/index/"

[net]
git-fetch-with-cli = true
```

没有这一步，`cargo build` 拉依赖会非常慢甚至超时。

---

## 5. 安装 VS 2022 生成工具（**需要管理员，会弹 UAC**）

> ⚠️ **坑 2**：Rust 在 Windows 上的 MSVC 目标必须有 `link.exe` + Windows SDK 的 `.lib`。
> 用 GNU 工具链（mingw）绕开是行不通的 —— Tauri 依赖的 `webview2-com-sys` 链接的是
> MSVC 格式的静态库，mingw 的 ld 链接不了。

```powershell
winget install --id Microsoft.VisualStudio.2022.BuildTools -e `
  --accept-package-agreements --accept-source-agreements `
  --override "--quiet --wait --norestart --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"
```

- 约 **3.6 GB**，10–25 分钟
- 会弹一次 UAC，**必须点「是」**，否则安装静默失败
- 安装器不支持自定义路径，只能落在系统盘（这是唯一必须占用系统目录的组件）

**验证**：

```powershell
& "C:\Program Files (x86)\Microsoft Visual Studio\Installer\vswhere.exe" -latest -products * `
  -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath
# 期望输出 ...\2022\BuildTools

Get-ChildItem "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Tools\MSVC"
Get-ChildItem "C:\Program Files (x86)\Windows Kits\10\Lib"
```

两个都要有输出（实测是 `14.44.35207` 和 `10.0.26100.0`）。

## 6. 编译并运行

```powershell
cd F:\TermDeck
scripts\build.bat        # 首次 8–15 分钟，产出 release exe
scripts\run.bat          # 打开窗口
```

开发模式（带热更新）：

```powershell
scripts\dev.bat
```

### 这几个 bat 干了什么

`scripts\_env.bat` 手工拼装 MSVC 环境，**不调用 `vcvars64.bat`**：

> ⚠️ **坑 3**：`vcvars64.bat` 内部会调用 `reg.exe` 查注册表。在启用了「命令安全 / 程序黑名单」
> 的机器上，`reg.exe` 被拦截，导致 `LIB` / `INCLUDE` 没被设置，链接时报
> `LNK1181: 无法打开输入文件 kernel32.lib`。
> `_env.bat` 直接用目录扫描定位 MSVC 与 SDK 版本，绕开注册表。

它做的事：

1. 扫 `VC\Tools\MSVC\14.*` 得到 MSVC 版本，扫 `Windows Kits\10\Lib\10.*` 得到 SDK 版本
2. 设置 `PATH`（cl.exe / link.exe / rc.exe）、`INCLUDE`、`LIB`
3. 设置 `CARGO_HOME` / `RUSTUP_HOME` 指向 `F:\TermDeck\.toolchain`

> 如果你的机器没有安全策略限制，用官方「x64 Native Tools Command Prompt」也完全可行，
> 效果等价。

## 8. 已知坑汇总

| # | 现象 | 原因 | 处理 |
| --- | --- | --- | --- |
| 1 | `curl` 下载 rustup-init 无输出直接中断 | 官方源在国内被阻断 | 走 `rsproxy.cn` |
| 2 | `npm install` 长时间无进展 | 官方 registry 不可达 | `.npmrc` 指 npmmirror |
| 3 | `LNK1181: 无法打开输入文件 kernel32.lib` | `vcvars64.bat` 依赖 `reg.exe`，被安全策略拦截 | 用 `scripts\_env.bat` |
| 4 | `rustup could not choose a version of rustc` | 没设 `CARGO_HOME`/`RUSTUP_HOME`，或没设默认工具链 | 见第 3 节验证段 |
| 5 | 编译超过 20 分钟没结束 | release 全量 LTO + `codegen-units=1` | 已改成 thin LTO + 16 单元，正常 8–15 分钟 |
| 6 | 窗口空白 / 白屏 | Win10 缺 WebView2 运行时 | 装 [WebView2 Evergreen](https://developer.microsoft.com/microsoft-edge/webview2/)（Win11 自带） |
| 7 | 浏览器预览正常、桌面版没输出 | 用了旧版前端产物 | 直接 `scripts\build.bat`，它会自动先跑 `npm run build` |
| 8 | **窗口全白、进程却在跑、`termdeck.log` 只有 `app starting`** | 用 `cargo build` 代替了 `tauri build`，缺 `custom-protocol` feature，二进制仍指向 `devUrl` | 一律用 `scripts\build.bat`（内部走 `npx tauri build`） |

## 10. 日常命令

```powershell
scripts\dev.bat             # 开发模式（热更新）
scripts\build.bat           # 生产构建（exe，不含安装包）
scripts\build.bat --bundle  # 生产构建 + NSIS 安装包
scripts\run.bat             # 启动已构建的 exe
scripts\test.bat            # Rust 单测
npm run dev                 # 只跑前端（浏览器 Mock 模式）
node scripts\shot.mjs       # UI 自动化回归
```

应用运行时数据全部放在**可执行文件同级的 `data/` 目录**，整个应用是自包含的（换机器拷贝即可带走配置与历史）。
若安装位置只读（例如装进 Program Files），会自动回退到 `%APPDATA%\as.ixuhan.termdeck\`。
状态栏右下角会显示当前数据目录，点一下直接在资源管理器里打开。

```
data/
├── workspace_state.json   会话树 / 布局 / 快捷指令快照
├── workspace_state.bak    上一版快照（主文件损坏时回退）
├── termdeck.db            SQLite 历史库（WAL）
├── termdeck.log           后端运行日志（数据目录、会话创建、落盘、错误）
├── presets.json           预设库
├── settings.json          应用设置
└── exports/               导出的指令集 JSON（导入从这里选）
```
