# 变更记录

## v0.3.1 — 自动更新

安装版可以自己检查并安装新版本。

- 启动 8 秒后静默检查一次更新，有新版才提示，检查失败不打扰
- 「设置 → 关于与更新」里可手动检查，显示版本号、更新说明、下载进度条
- 下载完用编译进二进制的公钥验证 Ed25519 签名，验签通过才调起安装程序，
  装完自动重启并恢复工作区
- 便携版不参与自动更新：数据跟着文件夹走，自动装到系统目录会产生两份副本，
  面板里改为提示下载新包覆盖
- 新增 `install_kind` 命令区分安装版与便携版
- CI 构建时用 `TAURI_SIGNING_PRIVATE_KEY` 签名并生成 `latest.json`
- 文档：[docs/UPDATER.md](UPDATER.md)

### 文件目录右键菜单

- 右键文件/文件夹弹出**真正的资源管理器菜单**（`IContextMenu`），而不是自绘菜单
- 因此「打开方式」「发送到」、属性、回收站删除，以及装过的 7-Zip / TortoiseGit 等
  shell 扩展都会出现，行为与 Explorer 完全一致
- 菜单在窗口线程用 `TrackPopupMenu` 弹出（需要消息循环），前端坐标按 DPI 缩放到物理像素

### 串口列表

- 左侧栏底部新增串口面板，显示端口名、设备描述与类型标签（USB / PCI / BT）
- 描述取自 SetupAPI 的 friendly name，与设备管理器一致；`serialport` 只会把蓝牙口和主板口都标成 Unknown
- 纯展示：不打开端口（打开会拉 DTR 并复位 USB 转串口芯片）
- 默认手动刷新，点 ⟳ 枚举一次；切到「1s」才每秒轮询，选择会持久化
- 自动刷新时标题下方显示 `● 每秒刷新 · HH:MM:SS`，时间随每次枚举推进
- 高度可拖拽（与右侧栏同一个 `.resizer-h` 拖拽条），高度写入 workspace_state
- 点右上角 chevron 收起成一行；头部样式与右侧「文件目录」一致
- 列表按端口号自然排序（COM9 在 COM10 之前）

### 终端内容跨重启恢复

- 用 xterm 的序列化插件把缓冲区存成 ANSI 文本，存在 `data/scrollback/<session>.ansi`
- 3 秒防抖落盘 + 关窗前补一次，异常退出最多丢最后 3 秒的输出
- 重开会话时先回放旧内容，加一条灰色分隔线，接新 Shell 的提示符
- 回放只用于显示，不会被当作输入或计入命令历史
- 全屏程序（vim/ssh）的备用缓冲区不保存——回放一个进程已经不在的 TUI 屏幕没有意义
- 单个快照上限 1 MB，超出时保留最新部分；场景设置里可关闭（「恢复上次的终端内容」）
- 主动关闭会话时一并删除该会话的快照
- 保存前剥离旧分隔线，重启多次不会把它堆成十几行

## v0.3 — 文件目录面板

右侧栏改为上下分屏，下半部分新增文件浏览器。

- **两种路径模式**：动态跟随终端 CWD（默认）/ 固定锁定当前路径；工具栏一键切换，固定时显示「已锁定」标记
- **工具栏**：面包屑路径（可点击回退）、模式切换、手动刷新、在资源管理器中打开、折叠按钮
- **文件交互**：单击文件夹进入、`..` 返回上一级、双击文件用系统默认程序打开、区分文件夹/文件图标、显示文件大小
- **会话隔离**：显隐、模式、固定路径、当前浏览路径都挂在该会话下，互不干扰
- **持久化**：写入 `workspace_state.json` 的 `directory_panel` 字段，冷启动原样还原
- **零监听**：Rust 侧只提供 `read_directory` / `open_path` 两个无状态命令，不注册任何文件系统 watcher；
  仅在刷新、进入子目录、CWD 变更三个时机读一次，面板折叠或会话在后台时不读取、不渲染
- 目录读取带容错：路径不存在时自动回退到最近的存在的上级，删除目录后不会卡死

### 同时修复

- PTY 创建时回传真实起始目录，文件面板首次打开不再空白
- 右侧栏宽度调整同时作用于两个面板
- **快捷指令面板改为固定高度 + 内部滚动**：之前指令条数一多，列表会把整个面板撑高，
  把「导出/导入指令集」顶到窗口外且无法滚动。现在只有列表是可伸缩子项（`min-height: 0`
  + `overflow-y: auto`），头部、预设栏、底部按钮固定不动，任何条数都在面板内部滚动
- 窗口较矮或被目录面板挤压时，快捷指令区保留 180px 下限，改由目录面板让位

## v0.2.1 — 历史交互增强

### 新增：输入框右侧的「清空历史」按钮

- 点击后先弹确认框，文案里带会话名，明确告知只影响当前会话
- 清空是会话隔离的：只删当前会话的历史行，其他会话的 Ghost Text 与检索完全不受影响
- 清空后同步重置历史游标与 Ghost Text 状态，并弹一条操作反馈
- 历史本身存在 SQLite，跨重启保留；这是唯一会删除它的入口（设置面板里也保留了同一个入口）


### 新增：↑/↓ 直接翻阅会话历史

输入框为空时按 `↑` 立刻载入本会话最近执行过的命令，继续按 `↑` 往前翻、按 `↓` 往后翻，
翻过最新一条会恢复成你原本输入的内容（草稿不会丢）。

- 后端新增 `history_recent` 命令，按 `executed_at` 倒序取，与按相关度排序的 `history_search` 分开
- 会话隔离保持一致：只翻当前会话的历史
- 与「↑ 采纳 Ghost Text」不冲突：只有在设置里勾选了 ↑ 采纳、且当前有预测时才优先采纳
- `scripts/regress.mjs` 增加 4 条断言，`scripts/app-e2e.mjs` 增加真实后端断言

## v0.2 — 首轮验收反馈修复

验收提出的 12 项问题全部处理，并补齐了自动化断言（`scripts/regress.mjs`）。

| # | 问题 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | 点 `+` 新建会话菜单显示异常 | 菜单 `right:0` 定位、宽 272px，而侧栏仅 240px，整块被挤出窗口左边缘 | 改左对齐 + 独立层叠上下文 + 超长可滚动 |
| 2 | 点关闭按钮软件退不掉 | `win.destroy()` 缺 `core:window:allow-destroy` 权限，静默失败 | 补权限 + 保存后强制 destroy，失败回退 close |
| 3 | 重启后命令历史消失 | 每次启动生成新 PTY id，历史按它索引 → 全部孤儿 | 拆成「稳定 `key`」+「临时 `ptyId`」 |
| 4 | 输入框左侧缺历史入口 | — | 新增历史按钮，点开历史浮层 |
| 5 | 载入模板后像所有会话都变了 | 实际只改当前会话，但下拉框不重置，切换会话仍显示模板名 | 切换会话时重置下拉 |
| 6 | 补全采纳按键不可配 | 硬编码 Tab / → | 设置里可勾选 Tab / → / Ctrl+→ / ↑，多选 |
| 7 | 预设导出导入走剪贴板 | — | 改为「导出/导入指令集」，写入 `<data>/exports/*.json`，导入带文件列表 |
| 8 | 切换会话后手动锁定失效 | `activate()` 无条件把 mode 重置为 input | 锁定时保持 passthrough |
| 9 | 锁定状态下点「填入」无反应 | 内容写进了被折叠的输入框 | 填入时自动退出直通并解除锁定 |
| 10 | 切换目录后重启回到默认目录 | `profile.cwd` 从不更新 | OSC 7 + `cd` 追踪双通道，实时写回并持久化 |
| 11 | 数据散落在系统盘 | 使用 `app_data_dir()` | 改为 `<exe 目录>/data`，状态栏显示路径并可打开 |
| 12 | 常驻内存偏高 | 所有会话无条件起 PTY | 恢复时按需启动、回滚行数可调、WebGL 可关 |

### 顺手修掉的 3 个内部缺陷

- **toast 永久悬浮挡住点击**：`.quick-notice` 没有 CSS animation，`onAnimationEnd` 永不触发，状态永不清理。补 fade 动画 + `pointer-events:none`。
- **受控输入字符错序**：`pendingCaret` 在值未变化时不被消费，残留条目会把后续输入的插入位置拉回旧光标（输入 `git` 变成 `itg`）。改为 `{text,pos}` 且仅在渲染值匹配时消费。
- **Vite 首次模块转换 33 秒**：`watch.ignored` 未排除 `.toolchain`（1.5 GB）与 `target`（2 GB），补上后 0.61 秒。

### 实测数据（2 会话 Idle）

| 项 | 数值 |
| --- | --- |
| termdeck.exe（Rust 宿主） | 66.6 MB |
| WebView2（6 进程） | ~439 MB |
| conhost + shell | ~88 MB |
| **合计** | **~593 MB** |
| 空闲 CPU（10s 采样） | **0%** |
| 关闭 WebGL 后 | 577 MB（省约 16 MB） |

WebView2 运行时本身即 400 MB 量级，SRS 中 150 MB 的目标在该技术栈上不可达。可用杠杆是「会话按需启动」与「减少同时打开的会话数」。
