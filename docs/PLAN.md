### 0.3 质量门禁定义

**DoR（任务可开工）**：需求编号已定 → 验收标准已写 → 接口契约已确认 → 无阻塞依赖。

**DoD（任务算完成）**：代码合并主干 → 关键路径有单测 → 对应验收用例手工跑通 → 日志/错误可观测 → 无新增 P0/P1 缺陷。

### 0.4 实施策略（关键决策）

**不采用「按模块并行铺开」的瀑布式排期，而采用风险前置的三段式：**

```text
① Spike 去风险  →  ② 垂直切片跑通  →  ③ 按模块增量填充
   （5 人日）         （10 人日）          （44 人日）
   验证 5 个         端到端最小闭环        功能、持久化、
   致命假设          （一个 Shell 跑通）    硬化、验收
```

**理由**：本项目的 5 个致命假设（ConPTY 行为、Alt-Buffer 检测、CWD 追踪、大吞吐背压、WebView2 资源基线）任一不成立，都会推翻部分需求设计。若按模块顺序开发，问题会在第 8 周才暴露，返工代价极高。Spike 阶段用 5 天把不确定性打掉，是整份计划里性价比最高的安排。

#### G0 门禁：指标复核会（0.5 天，含在 P0 内）

**必须当场做出 3 个决策并记入 SRS 修订**：

| 决策项 | 分支 A | 分支 B |
| --- | --- | --- |
| 冷启动指标（NFR-P1） | 实测 ≤700 ms → 坚持 600 ms 目标 | 实测 >900 ms → 改成「≤1000 ms 底线 + 600 ms 目标」，或引入托盘预热方案 |

| CWD 方案（R4） | OSC 7 覆盖 ≥3 类 Shell → 单通道 | 覆盖不足 → 双通道（OSC 7 + PEB），P5 工时 +1 |

> ⛔ **G0 未达成一致，不得进入 P1**。指标含糊会让 P6 的硬化阶段失去判据，变成无限优化。

| T3.8 | 手动切换 `Ctrl+Shift+P` + 状态栏模式指示器 + S3 锁定优先级 | FR-INPUT-04 | 0.5 | T3.7 |

**本阶段最高风险项是 T3.4 + T3.5 组合**。原因：Ghost Text 既要「准」（异步查询）又要「快」（16 ms 内呈现），二者天然冲突。推荐实现路径：

1. 前端维护一个**内存中的 Top-200 前缀索引**（随每次入库增量更新），按键时先在内存匹配 → 命中率高时 0 延迟出 Ghost Text；
2. 内存未命中才走 SQLite 异步查询；
3. 两条路径共用同一「序号」丢弃机制。

> 这套「内存热索引 + 落库冷查询」的双层设计不写进 SRS（属实现细节），但必须在 T3.4 开工前定下，否则会返工。

**G2 门禁：价值验证（可试用）** —— 邀请 2–3 名目标用户（含嵌入式/后端各一）实际使用 3 天，收集「输入体验是否真的比原终端好」的主观判断。**若 Ghost Text 或直通模式体验被判定为负分，需在此处决策是否调整产品方向**（例如把 Ghost Text 从默认开启改为可选）。这是整份计划中唯一的产品级止损点。

### 2.5 性能验收方案（L4）

> 原则：**每个指标必须有可复现的测量脚本 + 原始数据 + 采样次数**，不接受「感觉还行」。

| 指标 | 测量方法 | 采样 | 判据 |
| --- | --- | --- | --- |
| **NFR-P1 冷启动** | 加隐藏参数 `--bench-cold-start`，进程内打点：`T0=进程创建`、`T1=首帧渲染`、`T2=首个 Shell 提示符就绪`；脚本循环 20 次（每次彻底杀进程 + 冷缓存可选） | 20 次取 P50/P95 | P95 ≤ **底线值**（G0 决策后的值） |
| **NFR-P2 输入延迟** | 前端 `performance.mark` 埋点：keydown → 字符与 Ghost Text 完成绘制（`requestAnimationFrame` 后）；用自动化脚本按 10 字符/秒注入 | 200 次取 P95 | P95 ≤ 16 ms |
| **NFR-P3 内存** | 3 会话 Idle 静置 5 min 后，`Get-Counter '\Process(TermDeck*)\Working Set - Private'` 汇总所有子进程 | 10 次取均值/峰值 | 均值 ≤ 底线值 |
| **NFR-P4 检索响应** | 预置 5000 条历史，前端埋点 `Ctrl+R` 键入 → 首屏结果渲染完成 | 50 次取 P95 | P95 ≤ 10 ms |
| **NFR-P5 大吞吐** | `fsutil file createnew big.bin 104857600` 后 `Get-FileHash` 对比；同时注入 UI 心跳测最大卡顿 | 3 轮 | 哈希一致（0 丢字节）；UI 最大卡顿 ≤ 500 ms |
| **NFR-P6 空闲 CPU** | 3 会话 Idle，性能计数器采样 60 s | 3 轮 | 平均 ≤ 1% |

**数据留档**：每次测量输出 CSV（时间戳 / 指标 / 样本序列 / P50 / P95 / 环境信息），汇总进 D7。
